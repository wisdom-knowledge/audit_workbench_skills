# 每轮监听字段怎么猜

先拉 `field_groups`，再拿齐 `+field-list`，按**字段分组**、列名、类型、options **自己推断**每轮监听列。不要运行 `guess_round_fields.py` 或任何本地匹配/打分脚本。

只猜两类列：每轮「审核状态」和「审核员talent_id」。给用户的确认清单只放最佳猜测（列名 + `field_id`），不要解释推理过程。

`field_id` 必须来自 JSON 原值，禁止编造。同一字段最多归属一轮。名称明显属于其它轮次的列不要塞进本轮。约定名是强先验，括号、空格、初审/复审/人审/一轮/二轮/第 N 轮等变体按语义归轮。不确定或找不到：该项写「列名（疑似缺失）」，不要用弱匹配硬凑。

## 字段分组（先查，再缩小范围）

`+field-list` / `+table-get` **不含**分组。第二轮必须先查字段分组：

```bash
lark-cli api GET '/open-apis/base/v3/bases/<base_token>/tables/<table_id>/field_groups' --as user --format json
```

返回 `data.groups[]`：`id`、`name`、`type=group`，`children[]` 为 `{id, type: "field"}`。把 `children.id` 和 `+field-list` 的字段对上；某个 `field_id` 不在 list 里时 `+field-get` 补名字、类型、options。

分组名本身带轮次语义，**先按分组缩小候选，再在组内用列名、类型、options 定位**。只把名称表示审核轮次的组当作候选池，例如：

| 分组名语义 | 归轮 |
|---|---|
| `人审1` / `人审1相关` / `一轮` / `第1轮` / `初审` | 第 1 轮 |
| `人审2` / `人审2相关` / `二轮` / `第2轮` / `复审` | 第 2 轮 |
| `人审N` / `N轮` / `第N轮` | 第 N 轮 |
| `终审` / `终审信息` | 用户轮次里的终审或末轮 |

`盲审`、`再质检`、`回传`、`建议`、`评价`、产线阶段、看板、结算、元数据、跑分、题目、基础信息、系统等组不当本轮监听列来源。

本轮优先只在对应分组内找「审核状态」和「审核员talent_id」。组内命中即可用；组内没有该列就标「疑似缺失」，不要从其它轮次组或无关组里挪用。接口失败或 `groups` 为空时，再退回按列名全表推断。

## 排除

名称含：`盲审`、`更新时间`、`建议`、`评价`、`回传`。
类型：`button`、`formula`、`created_at`、`updated_at`。
名称含 `审核员talent_id` / `审核人talent_id` 时保留 `lookup`（底表常见类型）。

## 状态列

优先 `type=select`，名称表示该轮审核状态：

| 轮次 | 优先名称 |
|---|---|
| 1 | `审核状态`；其次 `人审1-审核状态` / `一轮审核状态` / `第1轮审核状态` / `首轮审核状态` / `初审状态` |
| ≥2 | `人审N-审核状态` / `N轮审核状态` / `第N轮审核状态`（三轮同理）；第 2 轮还认 `复审状态`；终审还认 `审核状态`（落在终审组时） |

## 审核人列

默认监听列是 `审核员talent_id`。人员列 `审核员` / `审核人` 不当监听列。名称应含 `审核员talent_id`（次选 `审核人talent_id`），允许 `lookup` / `text` 等，不要求 `type=user`。同表同时存在人员列和 talent_id 列时只猜后者。

| 轮次 | 优先名称 |
|---|---|
| 1 | `审核员talent_id`；其次 `人审1-审核员talent_id` / `审核人talent_id` / `一轮审核员talent_id` / `首轮审核员talent_id` / `初审审核员talent_id` |
| ≥2 | `人审N-审核员talent_id` / `N轮审核员talent_id` / `第N轮审核员talent_id`（三轮同理）；第 2 轮还认 `复审审核员talent_id` |

## 通过选项

从本轮状态列的 `options` 里找晋级通过选项。约定名：`审核通过`、`审核员修改后通过`；本轮前缀变体也算，例如 `人审3通过`。飞书常常不给 option id，只传 `name` 即可。

确认清单「晋级通过选项」必须写出当前选定的选项原文。约定名不齐时：先列出已选定的（例如 `人审3通过`），再加「（暂未找到其他晋级选项）」。禁止只写「（暂未找到其他晋级选项）」而把已选定的选项藏掉。

## 输出

给用户时只把最佳猜测填进确认清单（列名 + `field_id`）。猜不出时在该项写「列名（疑似缺失）」；通过选项不齐时写已找到的选项并加「（暂未找到其他晋级选项）」。出现疑似缺失时，清单末尾追加：「请人工检查疑似缺失的字段，如确认缺失请手动添加后我来重试；如存在，直接反馈给我指定字段」，并在这句话下面列出待检查项。待检查项的轮次、字段名、选项名必须与上面清单一致。晋级通过选项不齐时写成：「第 N 轮晋级通过选项：除了「{清单里已写出的选项}」之外还有没有其他选项」，不要在已选定 `人审3通过` 时改口写成「审核通过」。用户改列名后，用 `+field-list` 再取 `field_id` 和 option id。
