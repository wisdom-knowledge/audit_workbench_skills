# 版本说明

版本号同时写在 `.claude-plugin/plugin.json`、`.codex-plugin/plugin.json` 和
`audit_workbench_mcp/pyproject.toml`，三处保持一致，`check_setup` 返回的就是这个版本。

## 1.0.6

- 新增只读工具 `check_update`：对比本机插件版本和 GitHub main 上的版本，有新版本时按客户端（Claude Code /
  Codex）返回更新命令。入口技能把它作为第一步，每个会话第一次使用时调用；有新版本就在终端执行更新命令，
  请用户重启后再继续。查不到远端版本或开发者本地安装时按当前版本继续。

## 1.0.5

- 发布前「配置校验」只看后端发布预检：`check_readiness` 把 `errors` 和 `workflowErrors` 都记为
  blocker，不再在本地检查状态映射、审核员数量，也不再给 warning / unverified。
  `pre_publish_checklist` 的阻断项改为复用 `check_readiness`。
- 新增发布后「全链路校验」工具 `verify_pipeline`（只读），清单逐项打 ✅ / ❌ / ⏳：有审核员；
  每轮审核员 talent_id 字段是查找引用且引用的表在同一个多维表格里；「人才招聘」是底表可管理协作者；
  等待工作流创建完成。读不到的项算 ❌。
- 接入阶段 6 改为「全链路校验与交付」，全部 ✅ 后再写交付。

## 1.0.4

- 2.2 每轮拆成「字段映射」和「状态枚举映射」两张表，映射项不再带「字段」「状态」前后缀。新增 🟢
  置信度最高、可以不关注的项，排在 🔴、🟡 之后。
- 2.1、2.2、2.3 的「可以直接在配置页手动调整并保存」后加「（⭐️更快捷）」。
- 草稿和发布不再带全量字段池 `sourceFields`（后端不存，进配置页时从字段目录还原），`get_editor`
  返回的配置里也不再出现它，字段候选看 `fieldCatalog`。
- 交付的「仍需人工处理」只列未绑定飞书的审核员和模版二需人工同步的工作流，都没有时整段不写。

## 1.0.3

- 修正 2.2 映射确认的配置页链接：角色字段和状态枚举映射在配置页第 2 步「审核规则配置」，链接改为 `step=2`。

## 1.0.2

- 推荐配置 2.1、2.2、2.3 的每个确认节点，管理端配置页链接都放在最后一行，紧跟在「有需要调整的吗？
  可以直接在配置页手动调整并保存，也可以告诉我，我帮你调整」之后。2.3 的链接指向配置页第 2 步。
- `set_enqueue_views` 返回 `views_markdown`：每轮视图和筛选条件、还差的轮次，最后是配置页链接。
- 2.1 字段报告展示后不再追加待办或问题清单。

## 1.0.1

推荐配置报告的交互调整。

- 草稿已保存时，管理端配置页链接单独成块放在报告最前面，结尾再给一次。
- 「需要确认的字段映射」按轮次分开。每轮先列 🔴 没推荐出来、需要用户选的项，再列 🟡 系统自动推荐出来
  但是需要用户确认的项；不再使用「低置信」的说法。
- 推荐配置拆成三个子步骤逐步确认：2.1 展示字段、2.2 字段映射和状态枚举映射、2.3 入队条件。
  `suggest_draft` 一次返回三段文本（`report_markdown`、`mapping_markdown`、`views_markdown`）。
- `onboard_status` 返回配置页链接，从阶段 2 恢复时先问字段和映射是否已确认。

## 1.0.0

首个插件版本，一次安装入口技能、五个子技能和管理端 MCP。

- 入口 `audit-workbench`：定位环境和项目，按目标分发到接入、改配置、工作流、审核员、排障。
- 接入：推荐配置、发布前清单、工作流同步与启用、审核员绑定，可从线上状态续接（`onboard_status`）。
- 排障：`trace` 按 record_id 沿依赖链给出卡点；提交后判断结合审核日志、`task_submit` 事件和飞书当前值，
  结论待定时用 aliyun CLI 查 SLS 运行日志。
- 新增 `check_setup`：检查管理端登录态、lark-cli 用户身份和阿里云日志读权限，并返回版本。
- 删除旧的 `audit-workbench-enqueue-workflow` skill。入队工作流改由发布后的后端 Worker 创建，
  在插件里用工作流子技能查看、重试和启用。
