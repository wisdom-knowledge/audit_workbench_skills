# 审核工作台

按这次的目标进入一个子技能，只加载用得到的那个。环境、项目 ID 和已经查到的结果，在同一会话里
直接沿用，不重复查，也不重复问。

开始任何操作前，先完整读一遍 [通用规则](references/rules.md)。需要解释业务、模版差异，或判断
一条记录卡在哪一步时，读 [业务模型](references/business-model.md)。

## 定位项目

所有工具都要环境（boe / prod）和项目 ID。

- 用户这次给了，就用这次的；换了项目或环境，就以最新的为准，前面查到的结果作废。
- 没给但会话里有，直接沿用。
- 都没有就问：「请提供环境（boe / prod）和项目 ID。」环境不默认，不按链接或项目名猜。
- 只给了底表链接时，同样要问项目 ID。工具没有按链接反查项目的能力。

这个环境在本会话里第一次用时，先调用 `check_setup(env)`，把 `setup_markdown` 原样展示。
`ready=false` 时按「处理」列先解决，再往下做；只有阿里云日志一项不通过不影响使用。

拿到后调用 `get_editor(env, project_id)`，记下 `summary` 里的草稿时间、已发布版本、运行状态，
以及草稿或已发布配置里的 `workbenchType`（1 为模版一，2 为模版二），再交给子技能。

## 分发

| 用户要做什么 | 子技能 |
|-|-|
| 新项目接入，或已有项目重新走一遍接入 | [接入](../audit-workbench-onboard/SKILL.md) |
| 改字段、权限、布局、状态映射或入队视图，然后发布 | [改配置](../audit-workbench-config/SKILL.md) |
| 查工作流同步状态、重试失败的轮次、模版二人工修补、启用工作流 | [工作流](../audit-workbench-workflow/SKILL.md) |
| 增删审核员，查谁没绑定飞书账号 | [审核员](../audit-workbench-auditors/SKILL.md) |
| 某条记录为什么没进专家端、某人为什么看不到、提交后飞书为什么没变 | [排障](../audit-workbench-ops/SKILL.md) |

一个请求涉及多项时，按依赖先后串起来做，把前一步拿到的结果交给后一步。例如「把入队视图换掉
并重新启用工作流」，先走改配置，发布后再走工作流。
