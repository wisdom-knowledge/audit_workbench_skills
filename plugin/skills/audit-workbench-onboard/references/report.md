# 阶段 6：交付

汇总前面各阶段的结果，给用户一份简短的接入结论。按下面顺序写，不重复展示已经给过的报告全文。

1. 项目、环境、模版类型、已发布配置版本和发布时间。
2. 配置页链接（阶段 2 的 `page_url`）和各条工作流链接（阶段 4 的清单）。工具没返回的链接不要
   自己拼。
3. 已验证项：草稿回显、发布前检查、工作流同步与启用、审核员添加。只列真正调用过工具并拿到
   成功结果的，没做的不写。
4. 仍需人工处理：只列用户接下来必须动手做、否则项目跑不起来的事，就两类：未绑定飞书账号的
   审核员（用 🔴 标出并写明要通知其在专家端绑定）、模版二修补后仍需人工同步的工作流。两类都没有
   时整段不写。不要放进来：已经成功的项、对结果的观察或猜测、
   后端读不到但别的途径已确认成功的项、排查过程中顺带发现的问题。
5. 之后要改配置、处理工作流或审核员时，直接说目标即可，例如「第二轮加个字段」「加两个审核员」。

不要说「已跑通」。这里没有用真实记录走过入队到提交的链路，只交付「配置已完成，业务侧仍需验证」
的结论。第 3 项里证据缺失的写「未验证」，不要推断成成功。
